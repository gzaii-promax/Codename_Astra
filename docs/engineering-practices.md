# 可维护实现与开发评审

这是项目开发流程的约束，不是仅凭 lint、运行成功或测试数量判断质量。由 2026-10-05 工程调查及用户授权的一版修复形成；具体接口在模块 README 维护，失败与复验见 [工程契约记录](errors/ERR-20261005-ENGINEERING-CONTRACTS.md)。

## 实现前：配置和职责

- 可调输入、布局、角色参数、技能资源应有清晰的 Godot 编辑入口。输入默认保存在 Project Settings → Input Map；初始化只补缺失 action，保留已有绑定、deadzone 和有意清空的 events。场景/资源配置遵循 [Inspector 配置归属](inspector-configuration.md)，不要要求日常调试者手改文本才能生效。
- 先说明配置、派生值和运行状态分别由谁拥有。初始化与 reset 清状态，不重写保存配置；合法 `0` / `false` 不表示缺失。Inspector 范围提示与运行校验都需要：外部加载和代码赋值可以绕过编辑器提示。
- 按职责组合场景/组件。provider 返回值先检查对象类型与实例有效性，再判断具体组件类型（已释放引用不能直接做类型判断）。公共组件不猜测别的模块的子节点名或树层级；局部场景内部的固定路径可以作为明确的组合契约，跨模块依赖用可配置引用/路径或公开 provider 接口，并检查存在性与类型。
- 配置错误必须可诊断，并在对应功能入口拒绝执行。例如受击绑定失效不得报告命中成功；非法移动参数不得产生 NaN 物理速度。测试专用的无生命目标必须显式选择，不能作为正式绑定失效后的自动回退。

## 实现时：事件和生命周期

- 已发生的变化通过 signal 通知观察者；读取命令/查询仍使用明确接口。不要为“用了 signal”而把简单局部调用变成无目的广播。
- 事件参数直接携带本次结果，统计订阅者不用读取共享 `last_*` 字段来拼接事件。保留兼容事件时注明范围；事件中的 Resource/Node 引用仍是可变对象，不宣称整个 payload 不可变。
- Godot signal 默认同步调用，订阅者可能 reset、cancel、重新启动同名动作、删除节点或触发另一次命中。emit/外部回调后继续执行前，核对动作代次、对象有效性及取消状态；技能 ID 不能代替一次动作的身份。旧调用栈和旧 tick 剩余时间不能推进新动作。
- 运行时生成效果时显式登记世界、来源和来源中断策略。世界重置/切房按归属清理，角色中断按来源取消；不遍历根直属 children，也不枚举 Fireball/MeleeStrike 类型。近战随来源中断，已发射火球独立存续；跨世界迁移必须显式重新登记。
- 清理先在同一帧停止效果处理再 queue_free；物理扫描每次触发外部命中回调后重新检查效果是否已取消。节点层级、reparent、暂时离树都不改变归属契约；弱引用防止登记表延长节点生命周期。

## 评审和验收

涉及配置、依赖、事件或生命周期的改动按影响回答以下问题，相关答案及例外写入模块 README/PR；必要检查以 [测试分级](testing.md#按影响选择检查) 为准，纯文案不重复引擎复验：

| 检查 | 至少需要的证据 |
| --- | --- |
| 编辑配置后能否真正生效？ | 正式保存文件 → 无缓存重载/新引擎进程 → 入树 → 实际行为 → reset 后配置保留；合法零值另测 |
| 拆分场景、改名或增加容器是否安全？ | 公共依赖通过接口/显式绑定工作；错误路径与错误类型拒绝；实际 nested/reparent 与世界隔离反例 |
| 同步回调改变状态后旧流程是否继续？ | 同名动作重启、完成回调、命中回调再入、同帧效果取消等有针对性的引擎用例 |
| 新增同类内容需要修改哪里？ | 说明新技能/效果/房间的注册入口，清理不新增具体类型分支；涉及新机制再说明公共改动 |
| 代码是否易读且职责清楚？ | 公共接口/状态拥有者可定位，流程无隐式默认兜底；场景膨胀或程序建树例外记录原因与退出条件 |

公共工程契约修复先保留能复现问题的真实失败证据，再修复并立即运行适用验收。原失败、受影响回归和冻结源码的独立验证都要可读取；测试预期不能从 production 自动生成。无变化的文字收尾与关键证据归档按 [testing.md](testing.md) 执行。自动测试不代替编辑器易用性检查、实际画面和用户手感判断。

## 已知工程债

- `TrainingHUD` 是临时测试 HUD。用户确认当前版足够测试，后续完全重做。本轮保留代码和现有行为；运行时创建控件、父场景/Player 路径依赖、菜单与读数集中、逐帧刷新属于已知工程债，不作为正式 UI 的复用模板。债务和当前边界见 [ui/README.md](../ui/README.md)。正式重做时重新审查职责、可编辑场景和数据绑定，不把旧实现照搬为标准。
- `PlayerVisual` 仍运行时创建静态 Sprite，没有编辑器完整预览；安全修复只校验配置和有限几何值。火球等级/输入与角色注册仍是首版映射，未引入装备或完整技能树系统。地图 shape 细化诊断保留后续评估。训练地形现已保存为可编辑场景节点，出生位置通过 Marker2D 与显式路径配置，见 [世界模块](../world/README.md)。
