# 受击保护机制

## 已采纳需求

2026-10-02 用户要求：角色受到攻击后提供一段伤害保护时间，公共配置中记录常量；主角先定 0.5 秒，其他角色暂定 0 秒。角色保护时间为 0 时跳过伤害保护判定。

公共默认基线记录在 `shared/combat_config.gd` 的 `CombatConfig`；实际配置来源为每个角色场景中 `Combatant.hit_protection_seconds` 这个导出属性。个人计时由现有公共生命组件 `Combatant` 维护，不添加全局状态或 autoload。

## 本轮实现语义

- 有效攻击结算正伤害，且角色仍处于正常状态时启动保护。零心伤害的命中仍被接受，但不启动保护；无效数据、阵营排除与无敌拒绝也不启动。这是对未明确边界的本轮实现约定。
- 首次伤害正常扣血；0.5 秒保护期间拒绝后续普通伤害，不发命中/受伤事件，不触发新的受击中断，拒绝不续期。信号回调内的立即二次伤害同样被挡住。
- 保护时长以未暂停游戏时间计，物理帧递减；暂停冻结计时，重置清零。死亡/击倒/起身清除计时；剧情死亡仍可直接生效。保护不阻止角色操作，不切换既有无敌标志。
- 通用生命组件默认 0 秒，主角场景显式保存公共默认基线的 0.5 秒；运行时不重写已保存的 Inspector / 继承场景值。主角也可合法配置为零秒并直接旁路，不启动保护计时；训练重置保留配置，只清剩余计时。稻草人使用 10 个心容器与 REFILL，默认零秒保护。
- 既有近战只消耗成功命中的机会；保护结束而攻击窗口尚有效时，可接受同一窗口的首次伤害。火球接触目标仍消耗，受保护时不扣血。

没有增加视觉效果、敌人 AI 或新的技能规则。时长与手感仍由用户后续试玩调整。

## 可观察验收

1. 默认真实场景主角保护时长为 0.5 秒，敌人默认 0 秒，与公共默认基线一致；单个角色的实际配置入口为 Combatant 导出属性。
2. 主角首击正常扣血，保护期间同帧/后续攻击被拒绝，事件、心容器与动作中断不重复发生；拒绝不会延长保护，到期可再次受伤。
3. 0 秒角色连续接受有效伤害；运行时设为 0 清除保护并直接旁路。
4. 零伤害、不允许和无效攻击不启动保护；时长拒绝负数、非有限值。
5. 真实暂停/恢复、训练重置、剧情死亡、击倒/起身和既有可选恢复计时均保留约定；真实近战/火球覆盖保护后的碰撞语义。
6. 保留心系统与受击保护的完整用例；统一入口 `node tools/check.mjs --scope game` 核对完整报告、JUnit、日志和源码哈希。
7. 独立保存的主角场景覆盖 `0.0` / `0.2`，加载入树后分别连续受伤 / 使用 0.2 秒窗口；代码在入树前配置 `0.0` / `0.15` 亦保留。通过 PackedScene.pack、ResourceSaver.save、忽略缓存重新加载的完整往返，验证零秒不会因保存或初始化丢失。默认场景 0.5 秒另有固定基线用例，不从当前实现反取预期。

## 编辑与配置优先顺序

在自己拥有的编辑工作区打开 `player/player_character.tscn`，选择 `Combatant` 子节点，在 Inspector 编辑 `Hit Protection Seconds` 并保存。继承该场景时可在继承场景保存独立覆盖；需要修改某个已实例化角色时，先按 Godot 的场景编辑规则启用其可编辑子节点。当前角色配置遵循通用组件声明默认值 → 角色场景保存值 → 继承/实例场景保存覆盖 → 显式运行时代码赋值；不存在额外的 Player 初始化写入。

负数、INF、NAN 不会被悄悄改成默认值，仍由 Combatant.validate() 报错并拒绝伤害。修改某个角色的自定义时长无需修改公共常量；有意改变默认基线时同时维护常量、默认场景和基线验收，保留用户批准的原因。编辑所有权与保存交接遵循 [worktrees.md](worktrees.md)。

Godot 的导出值在对象构造之后加载，运行时读取应在加载后进行；本修复保留该加载顺序，不在 `_ready()` 再覆盖。依据：[GDScript exported properties](https://docs.godotengine.org/en/stable/tutorials/scripting/gdscript/gdscript_exports.html)。
