# 地图定义与连接

## 职责与编辑入口

`sample_world.tres` 是 3 房间世界的注册资源，可在 Godot Inspector 编辑。`MapRoomDefinition` 保存稳定 `room_id`、本地化标题 key 和可复用 `PackedScene`；`MapConnection` 保存来源房间/出口、目标房间/入口及可选能力要求；`MapRegistry` 查询房间与有向连接，并校验配置。房间模板、世界身份、运行状态分别维护。

当前房间 A/C 共用 `world/rooms/corridor.tscn`（512 × 256 px），B 使用 `hall.tscn`（768 × 256 px）。地形编辑与标记节点见 [房间说明](../rooms/README.md)，瓦片身份与替换约定见 [占位瓦片说明](../../assets/graybox/README.md)。

首版世界根与房间模板根节点使用 identity transform（零位置/旋转、单位缩放），房间 bounds 和地形在同一坐标系；调整房间大小时同步边界与地形。未来若允许变换房间，需增加边界坐标转换，不能只移动根节点而保留当前相机计算。

| 来源 | 目标 | 进入落点 |
| --- | --- | --- |
| room_a / east | room_b / west | (80,240)，朝右 |
| room_b / west | room_a / east | (432,240)，朝左 |
| room_b / east | room_c / west | (80,240)，朝右 |
| room_c / west | room_b / east | (688,240)，朝左 |
| room_c / return | room_a / start | (80,240)，朝右 |

双向通路由两条有向连接组成；没有隐式反向连接。A 的 return 和 C 的 east 没有路由，运行时隐藏并禁用，模板中仍可编辑。第一版一个来源出口最多有一个固定目标；动态选择目标是后续扩展，不使用多条相同来源消除歧义。

## 注册和校验

新增房间：从房间模板制作可编辑场景，在注册资源 rooms 数组增加独立身份/标题/场景，再在 connections 配置各方向的出口与入口。地图控制器不用增加房间专用切换分支。F3–F5 仅为当前 3 房间样例的调试快捷键，新房间无需绑定快捷键即可正常通行。

`get_room(id)` / `get_connection(room_id,exit_id)` 未找到时返回 null。`validate()` 检查空或重复房间身份、缺资源、模板类型与房间内部校验、初始房间/入口、连接源/目标存在、出口/入口存在以及重复来源。它临时实例化脱离场景树的模板并释放，不启动房间行为。校验错误是返回的数据，不关闭引擎报错机制。

`required_capability` 默认为空。世界层 `can_travel(connection)` 统一查询要求，`has_capability(key)` 为后续技能整合入口；第一版未授予任何非空能力，配置这种要求会拒绝通行，不以占位布尔值宣称已实现攀爬。

## 状态与扩展边界

探索记录属于 MapWorld 的本次会话，以稳定 room_id 保存。A/C 共享场景但探索身份独立，重复进入不会增加重复记录；R 重置、切出地图再返回或退出程序开始新会话。第一版没有磁盘存档或新宝箱玩法，未来对象状态使用 room_id 与房间内 object_id 定位，不能使用瓦片引用或模板文件名冒充对象实例身份。

加载与激活分开，出口节点只发送自身标识。转场、后台预加载、攀爬、动态目的地、世界总览和连接编辑面板的后续事项见 [地图系统契约](../../docs/map-system.md)。

## 运行碰撞调试

F6 切换 `CollisionDebug` 覆盖层；`MapWorld.set_collision_debug(enabled)` 也可设置。覆盖层读取当前房间实际瓦片碰撞多边形、玩家身体/受击区域及有效出口形状，随移动和切房更新，不改变物理资源。蓝色为地形、绿色为玩家身体、黄色为受击区、金色为出口；无路由出口不会绘制。当前支持矩形、圆形（24 边形显示）与瓦片多边形；新增其他 Shape2D 类型时补充绘制与验证。`collect_debug_polygons()` 返回覆盖层局部坐标，`get_debug_polygon_count()` 用于检查实际采集结果。

该显示层独立于 Godot 编辑器的碰撞提示开关，也不会将调试状态带到训练场。

## 验证

统一入口 `node tools/check.mjs --scope game` 核对固定连接图、实际 Area2D/键盘输入、共享模板的身份与探索、错误目标的原子失败、玩家状态保留、相机与暂停/重置、三语菜单和训练场往返、F6 实际几何显示。图形 probe 另捕获真实三语房间及碰撞调试画面；报告、人工查看与用户手感结论分别记录，文档不代表已通过。
